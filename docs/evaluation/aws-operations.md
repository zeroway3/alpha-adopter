# AWS 운영 실측 (2026-11-20)

`infra/scripts/cluster-up.sh`로 처음부터 올린 클러스터에서 실제 NAVER 뉴스를 수집하며 측정했습니다.
측정 후 `cluster-down.sh`로 내렸고, 남은 과금 리소스가 0인 것까지 확인했습니다.

- 환경: EKS 1.35, m7i-flex.large × 2, RDS PostgreSQL, ElastiCache Redis, Strimzi Kafka 4.3.2(단일 브로커),
  MongoDB, kube-prometheus-stack, NLB. 관련도 판단 claude-haiku-4-5
- 구성 스크립트는 첫 실전 실행에서 7단계 모두 수동 개입 없이 성공

## 알림 지연 (정상 상태 30분, 1분 주기 수집, 알림 약 120건)

| 구간 | p50 | p95 | p99 | 평균 |
|---|---|---|---|---|
| 수집 → 알림 (서버 내부: Kafka·매칭·AI 판단·저장·릴레이) | **1.7초** | **4.8초** | 6.3초 | 2.1초 |
| 기사 게시 → 알림 (사용자 체감) | 1.9분 | 3.1분 | 4.0분 | 2.0분 |

- 수집된 기사의 97%가 5초 안에, 100%가 10초 안에 알림으로 나갔습니다. Claude 판단 평균 0.77초.
- 게시→알림 2분의 대부분은 검색 API에 기사가 반영되는 시간과 1분 수집 주기입니다. 더 줄이려면 수집 주기
  (API 할당량과 트레이드오프)나 공시 같은 1차 소스가 필요합니다.

## 처리량 (news.raw에 100건 버스트 직접 주입)

| 구성 | 100건 처리 | 처리율 |
|---|---|---|
| 컨슈머 스레드 1개 | 87초 | 약 1.2건/초 |
| 컨슈머 동시성 3 (파티션 수) | **37초** | 약 2.7건/초 (2.4배) |

- 병목은 기사마다 순서대로 기다리는 Claude 판단(평균 0.74초)이었습니다. 이때 CPU는 4%라 **CPU 기준 HPA는
  파드를 늘리지 않았습니다.** I/O 대기로 막힌 파이프라인은 컨슈머 지연(lag) 기준 확장이 맞습니다(다음 과제).

## 부하테스트 (k6, NLB 경유, 최대 50 VU)

- 13,490건, 실패율 0%, 체크 100%. 전체 p50 9.6ms / p95 28ms
- 구독 조회 p95 37ms, 알림 이력 조회 p95 20ms, 구독 등록 p95 68ms
- 구독 등록의 IP 기준 한도 초과(429) 1,124건은 정상 방어라 지연 측정에서 제외

## 노드 장애 훈련

Kafka 브로커, Prometheus, core-service 파드 2개가 올라간 노드(2a)의 EC2를 강제 종료했습니다.

| 시점(종료 후) | 상태 |
|---|---|
| 0초 | 종료 명령. 서비스 준비 상태 200 유지(남은 파드가 처리) |
| +68초 | 관리형 노드그룹이 같은 AZ에 대체 노드 투입(Ready) |
| +102초 | Prometheus 복구(같은 AZ의 EBS 볼륨 재연결) |
| +113초 | Kafka 브로커 복구 |
| +124초 | core-service 3/3 준비 |

- **훈련 내내 외부 상태 확인이 200**이었고, **수집 유실 0건**이었습니다. 브로커가 없던 동안의 수집 1주기는
  지연됐다가 다음 주기에 58건을 정상 발행했습니다(수집 지점 덕분에 빈 구간 없이 이어받음).
- 훈련 직후 HPA가 파드를 줄일 때 **준비 상태 확인이 한 번 503**을 반환했습니다. 파드가 NLB에서 빠지기 전에
  먼저 종료됐기 때문이라 preStop 대기 20초와 graceful shutdown을 추가했습니다.

## 보안 실측

- 요청마다 다른 `X-Forwarded-For`를 보내도 11번째 로그인부터 429로 막혔습니다(위조로 rate limit 우회 불가).
- Redis의 rate limit 키가 로드밸런서 주소가 아니라 **실제 클라이언트 공인 IP**였습니다(NLB가 원래 IP 전달).

## 실측 중 찾아 고친 문제

| 문제 | 발견 경로 | 조치 |
|---|---|---|
| 알림을 받은 구독은 해지 불가(500) | 부하테스트 계정 정리 중 | FK에 ON DELETE CASCADE (V3 마이그레이션) |
| 처음 구독한 키워드의 과거 기사 약 1,300건이 한꺼번에 알림 | 정상 상태 지연이 비정상적으로 큼 | 첫 수집은 최근 60분 기사만 발행 |
| 처리량이 초당 1.2건에서 막힘 | 버스트 테스트 | 컨슈머 동시성 3 |
| 지연 분위수가 전부 30초로 잘림 | 지표 조회 | 히스토그램 범위 2시간 + 고정 경계값 |
| 축소 시 503 | 장애 훈련 후 | preStop + graceful shutdown |
