# 6단계 — AI 기반 관련도 판단으로 노이즈 필터링

## 문제

기존 매칭 로직(`NewsRawConsumer`)은 구독 키워드가 기사 제목/본문에 문자열로 포함되는지만
검사한다. 이 방식은 "키워드가 스치듯 언급되거나 우연히 겹치는" 기사도 그대로 알림으로
내보내는 노이즈 문제가 있다. 예를 들어 "카카오"를 구독하면 카카오(기업) 관련 기사뿐 아니라
초콜릿 카카오 함량을 다루는 요리 기사, 배우가 예전에 출연한 카카오TV 드라마 근황 기사까지
전부 알림이 간다.

## 해결

Claude Haiku(`claude-haiku-4-5-20251001`)로 문자열 매칭을 통과한 후보에 대해 실제
관련도를 0~100점으로 재판단하는 2차 필터를 추가했다 (`ai/ClaudeRelevanceClient.kt`,
`ai/RelevanceScorer.kt`). 임계값(기본 50점) 이상만 실제로 `Notification`을 생성하고
`news.matched`를 발행한다.

- `ANTHROPIC_API_KEY`가 설정되지 않으면 자동으로 비활성화되고 기존 문자열 매칭 결과를
  그대로 신뢰한다 — 로컬 개발 시 모든 기여자가 Claude 키를 가질 필요는 없음
- API 호출이 실패하면(레이트리밋, 네트워크 등) 안전하게 통과 처리(fail-open) — AI
  인프라 장애가 알림 전달 자체를 막는 단일 장애점이 되지 않게 함
- 판단에 사용한 점수는 `Notification.relevanceScore`에 저장 (AI 비활성화/실패 시 null)

## 실측 결과 (2026-09-05)

이전 단계(부하테스트, 실제 뉴스 수집)에서 실제로 쌓인 문자열 매칭 결과 30건을 그대로
Claude Haiku로 재판단해서, "기존 방식 vs AI 필터 적용" 결과를 비교했다 (합성 데이터가
아니라 NAVER API HUB로 실제 수집된 기사).

| 키워드 | 문자열 매칭 건수 | AI 통과(≥50점) | 평균 점수 |
|---|---|---|---|
| 카카오 | 9 | 1 | 23.9 |
| 삼성전자 | 11 | 8 | 64.1 |
| LG전자 | 10 | 3 | 36.0 |
| **전체** | **30** | **12** | — |

**노이즈 감소율: 60.0%** (문자열 매칭 30건 중 18건이 AI 판단으로 걸러짐)

키워드별 편차가 컸다는 점이 흥미로운데, "카카오"는 기업명이면서 동시에 초콜릿 원료·
드라마 제목("카카오TV")으로도 흔히 쓰이는 단어라 노이즈 비율(89%)이 가장 높았고,
"삼성전자"는 상대적으로 고유명사성이 강해 관련 기사 비율(73%)이 가장 높았다. 이는
단순 문자열 매칭이 애초에 "일반명사에 가까운 키워드"에서 특히 취약하다는 것을 보여준다.

## 비용

Claude Haiku 기준 건당 입력 ~500-800토큰 + 출력 수십 토큰 = 건당 약 0.1센트 수준.
이미 중복 제거(`existsByLink`)를 거친 신규 기사에만 적용되므로 실제 운영 시 호출량은
크지 않다 (키워드당 하루 수십 건 이내로 예상).
